## أقسام التطبيق التي تم فحصها

### 1. شاشة الترحيب والدخول

- ظهور شاشة الترحيب عند أول تشغيل.
- عدم ظهور حاوية التطبيق قبل الدخول.
- عدم تغطية شاشة الترحيب تلقائيًا بنموذج إعداد المكتب.
- وجود هوية المكتب والمالك والصفة المهنية.
- وجود الدخول إلى مكتب موجود، تسجيل مكتب جديد، واسترداد مكتب.

### 2. القائمة الجانبية والتنقل

- تحقق جميع روابط التنقل من وجود التبويب المستهدف.
- فحص عدم تداخل التبويبات داخل بعضها.
- ظهور جميع أقسام التشغيل الرئيسية.
- عدم وجود تمرير رأسي للقائمة الجانبية.
- وجود أيقونة المزامنة وأيقونة الإعدادات.
- ظهور تبويب **إدارة الملفات** بالاسم الجديد.

### 3. الأجندة

- وجود تبويب الأجندة.
- وجود زر الجلسات.
- وجود حاسبة المواعيد.
- وجود زر إضافة مهمة/حدث.
- التحقق من فتح مودال حاسبة المواعيد فعليًا.
- التحقق من فتح مودال إضافة مهمة/حدث فعليًا.

### 4. الجلسات

- فتح مودال الجلسات من داخل Electron.
- عدم وجود قسم جلسات الأسبوع أو الشهر داخل المودال.
- بقاء نموذج تسجيل الجلسة متاحًا.

### 5. إدارة الملفات وMJ

- وجود تبويب إدارة الملفات.
- وجود إنشاء ملف رئيسي وفتح الملفات الرئيسية.
- وجود فتح تفاصيل الملف وإضافة مرحلة.
- وجود منطوق الحكم وتاريخ الحكم.
- وجود أنواع مراحل التقاضي وربطها بالملف الرئيسي.

### 6. الأتعاب والمصروفات

- اختبار إنشاء أتعاب مرتبطة بالمرحلة والملف.
- منع المتبقي السالب.
- اختبار الدفعات والمصروفات.
- تلخيص إجمالي الأتعاب والمتحصلات والمصروفات وصافي الربح.
- التحقق من وجود طباعة تقرير الأتعاب.
- التحقق من سياق `legal_file_id` و`case_id` و`transaction_scope`.

### 7. الأرشيف والبحث والتقارير

- فتح تبويب الأرشيف دون صفحة بيضاء.
- فتح تبويب البحث والتقارير دون صفحة بيضاء.
- تحميل الإحصاءات في حالة عدم وجود مكتب أو بيانات.
- عرض الحالات الفارغة بطريقة آمنة بدل إطلاق خطأ Dexie.

### 8. التخزين والمزامنة والنسخ الاحتياطي

- وجود مخزن Dexie وإصدارات قاعدة البيانات المحلية.
- وجود طابور العمليات المعلقة.
- وجود التصدير والاستيراد الاحتياطي.
- وجود نقاط رفع وتنزيل المزامنة مع Supabase.
- وجود قيود المالك ومُعرّفات المكتب والترخيص.

### 9. الطباعة

- التحقق من وجود طباعة تقرير القضية.
- التحقق من وجود طباعة تقرير الأتعاب.
- لم يتم تنفيذ حفظ PDF فعلي ببيانات قضية حقيقية في هذا التشغيل لأن قاعدة الاختبار بدأت دون بيانات، ولأن ذلك يتطلب اختيار مسار حفظ أو بيانات اختبار مخصصة.

## أوامر الاختبار القابلة لإعادة التشغيل

```bash
npm test
npm run test:static
npm run test:electron
npm run test:comprehensive
```

يبدأ `test:electron` نسخة Electron مع شاشة افتراضية وملف تعريف معزول ثم يغلقها تلقائيًا بعد انتهاء الاختبار.

## ملفات الاختبار المضافة

- `test/comprehensive-static.test.js` — فحص ثابت شامل للهيكل والوظائف والروابط والمودالات.
- `test/electron-smoke.py` — فحص تشغيل فعلي عبر Chrome DevTools Protocol.
- `test/run-electron-smoke.sh` — مشغّل Electron مع Xvfb وملف تعريف مؤقت.

## حدود الاختبار الحالية

- لم تُنفذ عمليات كتابة أو Migration على Supabase، وفق نطاق الموافقة السابق.
- لم يُختبر اتصال Supabase الحقيقي أو فشل الشبكة في هذه الجولة؛ تم التحقق من نقاط التكامل الثابتة فقط.
- لم يتم إنشاء قضية تجريبية كاملة داخل الاختبار الآلي، لذلك يوصى بجولة قبول نهائية ببيانات تجريبية تشمل: ملفًا رئيسيًا، مرحلتين، جلسة، أتعابًا، مصروفًا، وطباعة PDF.
- لم يتم تغيير أي ميزة إنتاجية جديدة في شاشة الترحيب.

## توصية شاشة الترحيب

لا توجد ميزة جديدة ضرورية قبل اعتماد الشاشة الحالية. التحسين الاختياري المقترح لاحقًا هو إضافة **ملخص صغير أسفل شاشة الترحيب** يوضح:

- اسم المكتب.
- حالة التخزين المحلي.
- آخر وقت مزامنة.
- زر استرداد المكتب.

هذا تحسين معلوماتي فقط، ولا يُنصح بتنفيذه قبل موافقة المالك لأنه قد يزيد ازدحام شاشة الدخول.

## حالة المستودع

- الاختبارات مكتوبة وقابلة لإعادة التشغيل.
- لم يتم النشر.
- لم يتم تطبيق أي Migration على Supabase.
- تم إعداد أمر موحد: `npm run test:comprehensive`.
