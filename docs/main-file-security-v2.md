# الملف الرئيسي وإصلاحات الأمان — الإصدار 2

## نطاق التغيير

اعتمد تطبيق قيد `legal_files` بوصفه الملف الرئيسي الذي يجمع الملف القضائي أو الخدمي، مع الإبقاء على جدول `cases` للتوافق المرحلي. ترتبط القضايا والجلسات والمهام والملاحظات والمراحل والإجراءات بالملف الرئيسي عبر `legal_file_id`، ولا تُحذف الجداول القديمة أو البيانات الموجودة.

## حالات الملف

تُخزّن الحالة في قاعدة البيانات بقيم ثابتة باللغة الإنجليزية: `new`, `submitting`, `in_progress`, `needs_action`, `on_hold`, `completed`، و`archived`. تعرض الواجهة التسميات العربية المقابلة، وتحوّل الحالة القديمة `open` إلى `new` أثناء التنزيل أو الرفع.

## الصلاحيات

يمكن لعضو الفريق إنشاء ملف أولي فقط بحالة `new` أو `submitting`. تعديل الملف أو أرشفته أو تغيير بياناته الحساسة متاح للمالك فقط عبر سياسة `legal_files_manager_update`. تبقى العمليات المالية وتعديلات الجلسات الحساسة ضمن مركز اعتماد المالك كما هو موثق في `mobile-owner-approval.md`.

## إجراءات الخدمات والجلسات

أضيفت إلى `service_actions` حقول ترتيب الخطوة وحالتها وسبب التعطيل وتاريخ ومنفذ الإتمام. كما أضيف `session_status` إلى `sessions` لفصل حالة الجلسة عن حالة القضية القديمة `case_status`.

## حماية قاعدة البيانات

تستخدم Views `urgent_items` و`legal_file_timeline` و`office_financial_summary` الخيار `security_invoker = true` حتى تطبق سياسات RLS الخاصة بالمستخدم المستعلم. كما ثُبّت `search_path = public, pg_temp` للدالتين الحساسيتين `get_case_data` و`generate_case_code`، وسُحب تنفيذ الدوال الحساسة غير اللازمة من `PUBLIC` و`anon`.

أضيفت سياسات RLS لجداول `owner_recovery_codes` و`sync_operations` التي كانت مفعلة دون سياسات. بقيت دوال قبول الدعوات وبوابة العميل العامة مكشوفة عمداً لأنها جزء من التدفق العام المقرر؛ أما دوال المزامنة وإدارة المكتب والبيانات الداخلية فأصبحت متاحة للمستخدم المسجل فقط.

## المزامنة

ترفع نسخة الملف الرئيسي والمراحل القضائية قبل رفع القضايا التابعة، لتجنب أخطاء المفاتيح الأجنبية. وتُطبّع الحالات القديمة قبل الرفع. عند إنشاء قضية جديدة محلياً، ينشئ التطبيق ملفاً رئيسياً ومرحلة أولى ويربط القضية بهما، مع الاحتفاظ بمسار `cases` للتوافق مع الإصدارات السابقة.

## ملفات الترحيل المطبقة

- `supabase_migration_owner_file_security_v2.sql`: بنية الملف الرئيسي، الحالات، الخطوات، Views الآمنة، وسياسات الملف.
- `supabase_migration_security_hardening_v3.sql`: إصلاح View الملخص المالي، RLS للجداول الداخلية، وتقييد الاستدعاء من `anon`.
- `supabase_migration_security_hardening_v4_function_acl.sql`: إزالة صلاحيات `PUBLIC` الموروثة من دوال البيانات والمزامنة وإدارة المكتب.

## نتائج التحقق

نجح فحص JavaScript وHTML وتطبيق الهاتف TypeScript. أظهر Security Advisor بعد الإصلاح أن التحذيرات المتبقية تخص فقط دوال قبول الدعوات وبوابة العميل العامة المقصودة، إضافة إلى تحذير Supabase مستقل يتطلب تفعيل حماية كلمات المرور المسربة من إعدادات Auth، ولا يمكن تفعيله من migration SQL.
