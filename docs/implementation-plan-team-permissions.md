# خطة تنفيذ صلاحيات فريق قيد

**الهدف:** تمكين مالك المكتب من دعوة أعضاء بأدوار محامٍ وسكرتير ومحاسب، مع تطبيق الصلاحيات على سطح المكتب والهاتف وقاعدة البيانات.

**النطاق:** مستودعا `malegal/qayd` و`malegal/qayd-office-mobile`، مع اعتماد الأدوار الحالية `manager` للمالك و`lawyer` للمحامي و`staff` للسكرتير و`accountant` للمحاسب.

## قرارات الصلاحيات

| الدور | القراءة | الإضافة | التعديل/الحذف | المالية الحساسة |
|---|---|---|---|---|
| المالك | كل البيانات | كل شيء | كل شيء | يرى ويضيف ويعدل ويحذف |
| المحاسب | كل بيانات المكتب | دفعات الأتعاب والرسوم، المصروفات والرسوم، الملفات المهنية والقضائية | ممنوع | يرى المالية |
| المحامي | القضايا والجلسات والأسماء والملفات اللازمة للعمل | قضية، ملف مهني، جلسة، مهمة، ترحيل جلسة، إجراء، مصروف/رسوم | ممنوع | لا يرى مبالغ القبض إلا ما تسمح به شاشة الإضافة |
| السكرتير | القضايا والجلسات والأسماء والملفات اللازمة للعمل | نفس عمليات المحامي | ممنوع | لا يرى المالية الحساسة |

## التنفيذ

- إزالة علامة Q من هوية الشريط الجانبي، وإظهار كل التبويبات دون تمرير أفقي، وتحويل زر الإعدادات إلى أيقونة فقط.
- إضافة إدارة أعضاء المكتب داخل إعدادات سطح المكتب، مع دعوات واختيار الدور، وقائمة أعضاء وتغيير الدور/الإزالة للمالك.
- إضافة مساعد صلاحيات مشترك في الهاتف وتقييد الإجراءات السريعة حسب الدور، مع إبقاء الحماية النهائية في RLS وRPC.
- إضافة migration صريحة تمنع UPDATE/DELETE لغير المالك، وتسمح بإضافات كل دور حسب الجدول، وتمنع دوال المزامنة العامة من تجاوز عضوية المكتب.
- تشغيل `node --check` لسطح المكتب، و`pnpm check` و`pnpm lint` و`pnpm test` للهاتف، و`git diff --check` لكلا المستودعين.

## ملفات متوقعة

- `index.html`, `renderer.js` في سطح المكتب.
- `lib/office-data.ts`, `lib/office-permissions.ts`, `app/(tabs)/quick-actions.tsx`, `app/team.tsx` في الهاتف.
- migration جديدة في سطح المكتب لتطبيق قواعد RLS/RPC.
- اختبارات صلاحيات هاتفية ووثيقة مراجعة مختصرة.

## ملاحظات أمنية

لا تعتمد الواجهة وحدها على الإخفاء؛ يجب أن ترفض قاعدة البيانات العمليات غير المسموح بها. لا يتم تطبيق migration مباشرة على مشروع Supabase من هذه الجلسة دون معاينة مشروعه وتأكيد تطابق أسماء الجداول والدوال؛ سيُدفع ملف migration ليُطبق ضمن مسار النشر المعتاد.

## التحقق النهائي

لا تُعتبر المهمة مكتملة قبل نجاح الفحوص، مراجعة `git diff`, والتأكد من عدم وجود أسرار أو تغييرات خارج النطاق، ثم إنشاء commits منفصلة لكل مستودع ودفعها إلى GitHub.
